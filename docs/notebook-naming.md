# Notebook and report naming

Use lowercase words separated by hyphens for notebook names. Competition directories retain the exact slug from the Kaggle URL, including case. Use singular `experiment` consistently.

| Role | Notebook name | Example |
| --- | --- | --- |
| Data exploration | `eda.ipynb` | `eda.ipynb` |
| Controlled experiment | `experiment-<model>-<variant>.ipynb` | `experiment-cnn-baseline.ipynb`, `experiment-cnn-mixed.ipynb` |
| Final training and prediction | `submission-<model>.ipynb` | `submission-cnn.ipynb` |
| Consolidated methods and results | `report.ipynb` | `report.ipynb` |

Each experiment notebook documents its own method, settings, diagnostics, and observed results. Keep cross-experiment tables, graphs, and interpretations in `report.ipynb`, and link to that report from individual notebooks rather than duplicating comparisons.

Use a recognizable model name such as `cnn`, `kmeans`, or `catboost`. The variant identifies the experimental condition, such as `baseline`, `mixed`, `pixels`, or `pca`. Record exact epochs, random seeds, cluster counts, and other settings inside the notebook rather than encoding each parameter in its filename. Add a descriptive variant to a submission name only when separate submission pipelines need to coexist.

For example, a future K-means comparison can use `experiment-kmeans-pixels.ipynb` and `experiment-kmeans-pca.ipynb`. These names do not imply that those notebooks already exist.

## Matching files

Keep the same notebook stem across source, HTML, report manifest, and Kaggle configuration:

```text
competitions/<competition-slug>/
  experiment-cnn-baseline.ipynb
  experiment-cnn-baseline.kaggle.json
reports/<competition-slug>/
  experiment-cnn-baseline.html
  experiment-cnn-baseline.json
```

The report manifest is generated by `scripts/export_report.py`. The `.kaggle.json` file is a separate execution configuration; its `code_file` must match the notebook filename. Notebooks that are not pushed to Kaggle do not need a Kaggle configuration.

When pushing, prepare an ignored temporary directory containing only the stripped notebook source and its configuration copied to Kaggle's required name, `kernel-metadata.json`. Keep the original notebook filename in that package. Never push the whole competition directory, which can contain local data and credentials loaded by the notebook.

Renaming local files does not rename existing remote Kaggle notebook IDs or version links. Preserve the configuration's `id` and execution settings unless deliberately creating a different remote notebook.

## Renaming and publishing

Update notebook Markdown links, configuration `code_file`, documentation, and published report links together. Re-export from saved execution outputs and remove obsolete HTML/manifest paths. A filename or Markdown-only change does not require retraining; computational changes do.

The HTML URL follows the filename, so a rename changes the public URL after the `main` deployment. The Pages index is regenerated from current reports and does not list the old path. Older commits retain the previous files and LFS references.

Ignored artifact directories such as `output/baseline/` and `output/mixed/` are independent of these published filenames. This naming migration preserves their existing paths, data, trained weights, and saved execution outputs. Notebook output stripping and HTML storage in Git LFS remain unchanged.
